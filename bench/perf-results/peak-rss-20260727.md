# Install peak RSS reduction — 2026-07-27

## Scope

The install path now:

- decompresses an already-buffered tarball directly from its byte slice instead of copying the compressed input into a second `Vec`;
- acquires an extraction permit before releasing the corresponding download permit, bounding downloaded bodies waiting for extraction by the download pool;
- releases speculation-dispatch metadata before awaiting outstanding tarball tasks.

All comparisons used the release profile, the default mimalloc configuration, store v2, the proxy route, and three runs per case. Peak RSS came from `/usr/bin/time -l`; wall time is the install JSON `duration_ms`.

## End-to-end results

| Fixture | Metric | Baseline runs | Final runs | Median change |
|---|---:|---:|---:|---:|
| 256 packages, 32 roots, 512 versions/package, 256 KiB tarballs; cold store | peak RSS | 428.9, 438.3, 432.9 MiB | 431.3, 431.3, 447.3 MiB | 432.9 → 431.3 MiB (−0.4%) |
| same fixture; cold store | wall | 610, 623, 605 ms | 629, 595, 589 ms | 610 → 595 ms (−2.5%) |
| same fixture; warm store with a full resolve | peak RSS | 390.5, 382.6, 387.2 MiB | 387.0, 385.1, 390.4 MiB | 387.2 → 387.0 MiB (−0.1%) |
| same fixture; warm store with a full resolve | wall | 385, 374, 374 ms | 384, 376, 380 ms | 374 → 380 ms (+1.6%) |
| one package, 128 MiB decompressed tarball | peak RSS | 386.8, 374.1, 387.2 MiB | 272.8, 274.3, 273.6 MiB | **386.8 → 273.6 MiB (−29.3%)** |
| one package, 128 MiB decompressed tarball | wall | 343, 353, 349 ms | 323, 328, 339 ms | **349 → 328 ms (−6.0%)** |

The stable install outcome fields had zero differences for both the normal cold and large-tarball comparisons.

## Microbenchmark

`cargo bench -p lpm-extractor --bench decompress --locked -- buffered_input`

The fixture is a 16 MiB high-entropy gzip input. Both arms use the same libdeflate decode; only the old reader-copy versus direct-slice input path differs.

| Input path | Criterion estimate |
|---|---:|
| direct slice | 575.94 µs |
| reader plus compressed-input copy | 2.3811 ms |

The direct-slice path is 4.13× faster in the isolated input/decode benchmark and removes one compressed-size allocation.

## Rejected experiments

- Consuming registry packuments while building resolver cache entries changed the metadata-heavy median from 387.2 to 384.6 MiB but changed wall time from 374 to 383 ms. The RSS difference was only 0.7%, within run noise, so the broad resolver refactor was reverted.
- Switching from mimalloc to the existing `no-mimalloc` comparison build raised cold median RSS from 437.6 to 472.1 MiB and metadata median RSS from 384.6 to 414.9 MiB (both +7.9%). It was also slower, so allocator policy is unchanged.
